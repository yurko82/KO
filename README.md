# 📋 Автоматизована Система «Електронний журнал контрольних операцій (КО)»

Веб-додаток для автоматизації обліку, фіксації та аналітики виконання контрольних операцій під час ремонту обладнання енергоблоків **ВВЕР-440** (Блоки №1, №2) та **ВВЕР-1000** (Блоки №3, №4).

## 🚀 Основні можливості системи

### 1. 📊 Дашборд та оперативна аналітика (`DashboardView`)
* Лічильники виконаних операцій за сьогодні, загальна кількість агрегатів та відсоток готовності бази.
* Live-стрічка останніх прийнятих операцій у реальному часі.
* Підсумкова аналітика виробітку по кожному з контролерів (коди 1–7).
* Таблиця оперативного стану обладнання з прогрес-барами виконання.

### 2. 📋 Журнал контролю / Матриця КО (`ControllerView`)
* Інтерактивна матриця контрольних операцій за напрямками (**Насоси**, **Посудини**, **Арматура**, **Дизелі**, **Реактор**).
* **Зафіксована колонка (`Sticky column`)**: KKS-код та назва обладнання залишаються зафіксованими зліва при горизонтальній прокрутці великої кількості операцій.
* **Миттєвий пошук**: Поле `🔍 Пошук` для швидкого відбору обладнання за KKS, назвою чи підрозділом.
* Розширені підказки (tooltips) при наведенні на прийняті комірки з вказівкою ПІБ контролера та дати.

### 3. 🔐 Рольова авторизація та безпека (`AuthManager`)
* **Спостерігач (Гість)**: Режим тільки для перегляду.
* **Контролер**: Можливість фіксації операцій від свого імені (підтвердження PIN-кодом, наприклад `1111`–`7777`).
* **Адміністратор (Керівник)**: Повний доступ до Меню керівника (PIN за замовчуванням: `1234`).

### 4. 🔄 Смарт-синхронізація (Smart Merge)
* При записі у спільний мережевий JSON-файл система автоматично зчитує актуальний стан з диска та об'єднує відмітки `checks` та `audit_feed`, виключаючи втрату даних при одночасній роботі кількох користувачів.

### 5. 📜 Повний Журнал аудиту (`AuditView`)
* Окрема вкладка з детальною історією всіх дій (додавання відміток та їх скасування).
* При скасуванні відмітки вимагається обов'язкове вказання причини/коментаря.

### 6. 🖨️ Друк Актів та Експорт в Excel (`ExportManager`)
* **📥 Excel**: Експорт активної ремонтної бази у формат `.xls` з підтримкою UTF-8.
* **🖨️ Друк**: Генерація форматованої друкованої відомості контролю обладнання (Акт КО) з полями для підписів.

### 7. 📱 PWA та Офлайн-режим (Service Worker)
* Можливість роботи без мережевого підключення завдяки автономному кешуванню ресурсів (`manifest.json`, `sw.js`).

## 🗄️ Структура каталогу та файлів проекту

```
j:/site/KO/
├── index.html                   # Головна сторінка та каркас інтерфейсу
├── README.md                    # Опис проекту, поточний стан та історія оновлень
├── manifest.json                # Маніфест PWA додатку
├── sw.js                        # Service Worker для офлайн-кешування
├── css/
│   └── style.css                # Основні стилі додатку, адаптивна сітка та sticky-колонки
├── data/
│   ├── active_repairs.json      # Загальна мережева база даних ремонтних баз та відміток
│   └── catalog.json             # Структурований довідник обладнання (Блоки 1-4)
├── js/
│   ├── app.js                   # Головний контролер додатка та обробники подій
│   ├── auth.js                  # Модуль авторизації та розмежування прав (RBAC)
│   ├── storage.js               # Модуль зчитування/запису JSON та Smart Merge
│   ├── catalog.js               # Штатний каталог та асинхронне завантаження
│   ├── dashboard.js             # Відмальовування дашборду та KPI
│   ├── controller_view.js       # Відмальовування матриці журналу контролю
│   ├── audit_view.js            # Відмальовування Журналу аудиту
│   ├── admin_view.js            # Меню керівника (формування та редагування баз)
│   └── export_archive.js        # Модуль експорту в Excel та друку звітів
└── Журнал контр. операцій блок №1-4(clean).xlsm # Вихідні журнали у форматі Excel
```
